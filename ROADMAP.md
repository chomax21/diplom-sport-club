# План разработки адаптивного UI

Поэтапный план фронтенда информационной системы спортивного клуба.
Файл служит точкой навигации: здесь фиксируются этапы, решения, критерии
готовности и фактический прогресс.

- **Последний завершённый этап**: F6 — клиенты, тренеры, залы, пользователи
- **Следующий этап**: F7 — дашборды и отчёты
- **Статус**: справочники и пользователи проверены для admin; тренер видит клиентов только для чтения
- **Последний коммит бэкенда**: `d34bb67`
- **Репозиторий**: https://github.com/chomax21/diplom-sport-club
- **API**: http://localhost:8000/api/v1, документация — http://localhost:8000/docs

## Как пользоваться планом

Обозначения:

- `[ ]` — не начато
- `[>]` — в работе (одновременно только один этап)
- `[x]` — готово
- `[!]` — заблокировано, причина указана рядом

Правила:

1. Перед началом этапа перевести его в `[>]`, после завершения — в `[x]`.
2. Обновлять «Текущий этап» и журнал прогресса после каждого этапа.
3. Не начинать следующий этап, пока не выполнены критерии готовности текущего.
4. Фиксировать принятые решения в разделе «Решения» и коммитить изменения.
5. После каждого завершённого этапа делать отдельный коммит и push.

## Архитектура фронтенда

Плановая структура:

```text
frontend/
├── src/
│   ├── api/            # Axios-клиент, эндпоинты, типы ответов
│   ├── app/            # провайдеры, глобальные стили
│   ├── components/     # ui, layout, form-компоненты
│   ├── composables/    # общие composables
│   ├── features/       # auth, schedule, memberships, payments, admin, reports
│   ├── pages/          # страницы маршрутов
│   ├── router/         # маршруты и guard'ы
│   ├── stores/         # Pinia: авторизация и UI
│   ├── lib/            # форматирование, константы, утилиты
│   └── main.ts
├── public/
├── .env.example        # VITE_API_URL
├── Dockerfile
├── nginx.conf
└── package.json
```

Базовые принципы:

- API-база задаётся через `VITE_API_URL`, по умолчанию
  `http://localhost:8000/api/v1`.
- Серверное состояние — TanStack Query; Pinia хранит только авторизацию
  и UI-настройки.
- Access-токен хранится в памяти, refresh-токен — в localStorage.
  Axios-интерceptor при 401 обновляет пару токенов один раз и повторяет запрос.
- Ошибки API приходят в формате `{"detail": "..."}`; 401 — истёк access-токен,
  403 — нет прав, 409 — бизнес-конфликт, 502 — ошибка платёжного провайдера.
- Пагинация — `{items, total, limit, offset}`; список фильтруется параметрами
  `limit` и `offset`.
- Даты и время тренировок передаются в ISO 8601 **с часовым поясом**
  (`2026-11-01T18:00:00Z`), иначе бэкенд вернёт 422.
- Ролевая модель: `admin`, `trainer`, `client`; меню и маршруты строятся
  по роли, но проверка прав дублируется на бэкенде.
- UI-тексты на русском, форматирование дат и денег — через `date-fns`
  и `Intl.NumberFormat`.

## Контракт API для UI

Основные маршруты (префикс `/api/v1`):

| Экран | Эндпоинты |
| --- | --- |
| Вход и сессия | `POST /auth/login`, `POST /auth/token`, `POST /auth/refresh`, `GET /auth/me`, `POST /auth/register` |
| Расписание | `GET/POST /sessions`, `GET/PATCH /sessions/{id}`, `POST /sessions/{id}/cancel`, `GET/POST /sessions/{id}/enrollments` |
| Мои записи | `GET /enrollments/my`, `DELETE /enrollments/{id}` |
| Посещаемость | `POST /enrollments/{id}/attend`, `POST /enrollments/{id}/no-show` |
| Виды абонементов | `GET/POST /membership-types`, `GET/PATCH/DELETE /membership-types/{id}` |
| Абонементы | `GET /memberships`, `GET /memberships/{id}`, `POST /memberships/purchase`, `POST /memberships/{id}/cancel` |
| Платежи | `GET /payments`, `GET /payments/{id}`, `POST /payments/{id}/refund` |
| Клиенты | `GET /clients`, `GET /clients/me`, `PATCH /clients/me`, `GET/PATCH /clients/{id}` |
| Тренеры | `GET /trainers`, `GET/PATCH /trainers/me`, `GET/PATCH /trainers/{id}` |
| Залы | `GET/POST /rooms`, `GET/PATCH/DELETE /rooms/{id}` |
| Пользователи | `GET/POST /users`, `GET/PATCH/DELETE /users/{id}` |
| Отчёты | `GET /reports/attendance`, `GET /reports/revenue` |
| Служебное | `GET /health` (без префикса) |

Статусы для бейджей:

- абонемент: `pending`, `active`, `expired`, `cancelled`;
- запись: `active`, `cancelled`, `attended`, `no_show`;
- платёж: `pending`, `succeeded`, `failed`, `refunded`;
- способ оплаты: `card`, `cash`, `online` (наличные оформляет только админ).

## Требования к адаптивности

| Ширина | Поведение |
| --- | --- |
| 360–479 px | Одна колонка, drawer, полноэкранные модальные окна, карточки вместо таблиц |
| 480–767 px | Одна-две колонки, компактные фильтры, карточки |
| 768–1023 px | Две колонки, сворачиваемый sidebar, таблицы при достаточной ширине |
| 1024–1279 px | Постоянный sidebar, таблицы, две-три колонки |
| 1280 px и выше | Максимальная ширина контента, расширенные таблицы и графики |

Обязательные правила:

- минимальная поддерживаемая ширина — 360 px;
- отсутствие горизонтального скролла на всех страницах;
- кнопки и ссылки с touch-зоной не меньше 44×44 px;
- формы на мобильных в одну колонку;
- фильтры не занимают весь экран при открытии;
- длинные таблицы имеют горизонтальный скролл только внутри контейнера;
- модальные окна закрываются по Escape и клику по фону;
- все состояния (loading, empty, error) адаптивны.
