# Краткая выжимка

Информационная система спортивного клуба — REST API и адаптивное SPA для
учёта клиентов, тренеров, расписания, абонементов, платежей, записи на
тренировки и посещаемости.

Подробное описание: [DETAILED.md](DETAILED.md).

## Технологии

| Часть           | Стек                                                                           |
| --------------- | ------------------------------------------------------------------------------ |
| Backend         | Python 3.12, FastAPI, Pydantic 2, SQLAlchemy 2 (async), PostgreSQL 16, Alembic |
| Аутентификация  | JWT, Argon2                                                                    |

## Роли

| Роль          | Что может делать                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| Клиент        | Покупать абонемент, смотреть расписание, записываться и отменять запись, видеть свои платежи и профиль  |
| Тренер        | Вести своё расписание, смотреть записавшихся, отмечать посещение или неявку, смотреть свой отчёт        |
| Администратор | Управлять пользователями, клиентами, тренерами, залами, абонементами, платежами, расписанием и отчётами |

## Основные функции

- регистрация, вход, JWT-сессия и восстановление после перезагрузки;
- ролевые маршруты и меню, проверка прав на backend;
- расписание с фильтрами по дате, тренеру и залу;
- создание, редактирование и отмена тренировок;
- запись клиента, отмена записи, список участников;
- контроль мест, пересечений, занятости тренера и зала;
- виды абонементов и покупка через mock-провайдера;
- наличная оплата только администратором;
- история платежей, детали и возвраты с отменой абонемента;
- клиенты, тренеры, залы и пользователи;
- ролевые дашборды;
- отчёты по посещаемости и выручке, графики, таблицы и CSV;
- адаптивность 360–1440 px и доступность WCAG AA.

## Как проходит работа

1. Администратор создаёт залы, тренеров, виды абонементов и тренировки.
2. Клиент регистрируется или входит в систему.
3. Клиент покупает абонемент; после оплаты тот становится активным.
4. Клиент выбирает тренировку и записывается на неё.
5. Backend проверяет абонемент, остаток визитов, свободные места и пересечения.
6. Тренер открывает список записавшихся и после занятия отмечает посещение
   или неявку.
7. Посещение списывает один визит, неявка — нет.
8. Администратор контролирует платежи, оформляет возвраты и смотрит отчёты.

## Быстрый запуск

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec backend python -m app.seed

cd frontend
npm install
cp .env.example .env
npm run dev
```

- API: http://localhost:8000
- Swagger: http://localhost:8000/docs
- Frontend: http://localhost:5173
